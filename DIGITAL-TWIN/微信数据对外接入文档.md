# 微信数据对外接入文档

> 适用环境：本机 macOS + YoBot Recovered（内嵌 YokoWebot RPA 2.0.0）
> 编写时间：2026-09-21
> 目的：让**其他 Agent / 自建服务 / CRM** 能够读取或调用本机微信数据与能力。
> 说明：本文只写**本机实测可确认**的内容；凡未验证的一律标 ⚠️，不编造接口与字段。

---

## 0. 结论速览

| 通道 | 形态 | 鉴权 | 本机验证状态 | 推荐度 |
|---|---|---|---|---|
| **A. 官方 MCP** | Streamable HTTP，`POST http://127.0.0.1:<随机端口>/mcp` | `Authorization: Bearer <token>` | ✅ 代码与监听已确认，工具集 7 个 | **首选** |
| **B. RPA 本机 HTTP API** | FastAPI，`http://127.0.0.1:9922`（有 `/docs`） | `X-API-Key` + `X-Channel-ID`（临时凭据） | ⚠️ 端口实测在听；外部程序能否鉴权**未验证** | 不推荐直连 |
| **C. 直接读本地文件** | JSONL / SQLite / JSON | 无（文件权限） | ✅ 路径与结构实测 | 离线场景首选 |

**一句话**：要让**别的 Agent** 调用，请走 **通道 A（MCP）**；只做离线取数、不想依赖 RPA 运行时，走 **通道 C**；通道 B 是 RPA 内部接口，外部进程通常拿不到凭据，不建议依赖。

## 2. 通道 A：官方 MCP（推荐）

### 2.1 架构（谁提供、谁代理）

```
外部 Agent ──(Streamable HTTP + Bearer)──▶ 本机 MCP 服务（127.0.0.1 随机端口 /mcp）
                                              │  macOS 上由 YoBot 恢复版主进程提供
                                              ▼
                                    RPA 控制 API（127.0.0.1:9922 /api/...）
```

- 开关状态保存在：`~/Library/Application Support/YoBot-Recovered/config.json` → `mcpGateway`
  ```json
  { "enabled": true, "port": 9922, "token": "<redacted>", "exposedSkills": ["wechat-rpa"] }
  ```
  （当前 `enabled: true`。文件权限 `600`。）
- **对外暴露的技能白名单**只有 `wechat-rpa`。`shell / filesystem / scheduler / session / task_group / agent_records / mcp` **永不对外**（硬编码黑名单，纵深防御）。
- 原版 RPA 2.0.0 没有这个接口，所以恢复版在 `/api/mcp/control` 返回 404/405 时启用了本机兼容实现（`recovery-mcp.js`），只在**本机回环 + 随机端口 + 独立随机 Bearer**，关闭开关即关闭监听，令牌不写日志。

### 2.2 前置：拿到 endpoint 与 token

在 **App 的「对外开放」页**（MCP 网关）打开开关 → 页面展示 `url / port / token / capabilities`，可点「重新生成」轮换 token。

> ⚠️ token 是**进程内随机生成**的，重启后会变。请以页面显示为准；不要写死到代码里。
> ⚠️ macOS 上真正的服务端口是**随机回环端口**（不是 9922）；`config.json` 里的 `port: 9922` 是网关的默认/参考值。

### 2.3 传输与鉴权约定（实测自服务实现）

| 项 | 要求 |
|---|---|
| 路径 | `POST /mcp`（唯一路径，其余返回 404） |
| `Host` 头 | 必须是 `127.0.0.1:<端口>`，否则 403 |
| `Origin` 头 | **存在即 403**（浏览器页面调不通，这是故意的） |
| `Authorization` | `Bearer <token>`，常数时间比较；不符 → 401 |
| `Content-Type` | 必须 `application/json`，否则 415 |
| 方法 | 只接受 POST；GET（SSE 流）**不提供** → 405 |
| 请求体上限 | 64 KB（超过 413） |
| 协议版本 | `2025-03-26` / `2025-06-18`（其它值回落到 `2025-03-26`） |
| 响应模式 | JSON 响应模式（非 SSE） |
| 批量请求 | 不支持（JSON 数组 → `-32600`） |
| 通知（无 `id`） | 返回 `202`，无 body |
| 超时 | 服务端 `requestTimeout = 400s`；通讯录同步最长可到 3660s |

### 2.4 工具清单（7 个）

| 工具名 | 入参 | 只读 | 后端接口 | 说明 |
|---|---|---|---|---|
| `wechat_status` | — | ✅ | `GET /api/agent/instances_status` | 读取本机微信账号与 RPA 状态 |
| `wechat_list_history_sessions` | — | ✅ | `GET /api/chat/history_sessions` | 已采集聊天记录的**会话索引**（不是完整微信历史）。返回的 `account_id` + `session_id` 供下方工具使用 |
| `wechat_get_history_messages` | `account_id`, `session_id` | ✅ | `GET /api/chat/history_messages/{session_id}?account_id=` | 读取某会话**已保存**的聊天记录，不保证完整；`session_id` 必须来自索引 |
| `wechat_list_contacts` | `account_id` | ✅ | `GET /api/contacts?account_id=` | 已同步到本机的好友列表 |
| `wechat_list_groups` | `account_id` | ✅ | `GET /api/contacts/groups?account_id=` | 已同步到本机的群聊列表 |
| `wechat_sync_contacts` | `account_id`, `type`(`friend`\|`group`) | ❌ 有副作用 | `POST /api/contact/sync` | **会驱动桌面微信界面**做通讯录同步，耗时数分钟；勿与其他桌面操作同时跑 |
| `wechat_send_message` | `account_id`, `user`, `message` | ❌ 不可撤销 | `POST /api/chat/send_message` | 向指定好友/群发文字 |

**入参校验规则**：`account_id` ≤128 字符；`user` ≤256；`message` ≤10000；`session_id` ≤512 且**不含** `/ \` 与控制字符、不等于 `.`/`..`；未在 schema 中声明的字段会被拒绝（`-32602`）。

> ℹ️ 项目 README 里写「四个工具」是旧版本；**实际运行的是 7 个**（`toolset_version: 2`）。

### 2.5 JSON-RPC 交互示例

`initialize`：

```json
{"jsonrpc":"2.0","id":1,"method":"initialize",
 "params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"crm-bot","version":"1.0"}}}
```

响应：

```json
{"jsonrpc":"2.0","id":1,
 "result":{"protocolVersion":"2025-03-26",
           "capabilities":{"tools":{"listChanged":false}},
           "serverInfo":{"name":"yobot-local-compat","version":"1.1.0"},
           "instructions":"本机兼容接口。列表来自本地缓存；同步会操作桌面微信，并可能返回当前原生模块的兼容错误。"}}
```

`tools/list` → 返回 `{tools:[...]}`；`tools/call`：

```json
{"jsonrpc":"2.0","id":2,"method":"tools/call",
 "params":{"name":"wechat_list_history_sessions","arguments":{}}}
```

工具结果统一包在 `content` 里，且带 `isError`：

```json
{"jsonrpc":"2.0","id":2,
 "result":{"isError":false,
           "content":[{"type":"text","text":"<后端原始 JSON 文本>"}]}}
```

> 判定成败请看 **`isError`**：它综合了 HTTP 状态、`success !== true`、以及响应体里的 `success:false` / `error` 字段。业务失败原样透传，不会被吞掉。

### 2.6 外部客户端接入配置（示例）

任何支持 **Streamable HTTP** 的 MCP 客户端都可接入：

```json
{
  "mcpServers": {
    "wechat-local": {
      "type": "http",
      "url": "http://127.0.0.1:<对外页显示的端口>/mcp",
      "headers": { "Authorization": "Bearer <对外页显示的 token>" }
    }
  }
}
```

⚠️ 注意：**不要**在 HTTP 客户端里额外加 `Origin` 头，也不要用浏览器/网页前端去调（会被 403）。

## 3. 通道 B：RPA 本机 HTTP API（9922）

### 3.1 基本信息

- 基址：`http://127.0.0.1:9922`（实测 `lsof`：`YokoWebot ... TCP 127.0.0.1:9922 (LISTEN)`）
- 同时提供前端页面与 `/docs`（FastAPI 自带的交互式文档）
- 仅监听回环；未启动 RPA 或 Worker 重启期间不可用

### 3.2 鉴权

请求头需要：

```
X-API-Key: <凭据>
X-Channel-ID: <通道标识>
```

- 恢复版 Electron 主进程使用**每次启动重新生成的临时凭据**，只存在内存里，**不写文件、不下发给渲染进程**。因此**外部独立进程默认拿不到**。
- ⚠️ 随应用发布的前端 JS 里硬编码了一个占位值（`X-API-Key: yoko_test`）。**未验证**该值对 `/api/**` 真实有效，请勿据此搭建生产链路。
- 结论：**不要把通道 B 当对外接口**。外部 Agent 请走通道 A。

## 5. 多账号（重要）

- 本机可能同时登录多个微信号。**账号标识以"当前在线实例"为准**，历史账号（含已退出登录的）不能用来选执行账号。
- 通道 A 的每个工具都要传 `account_id`；不传或传错会有歧义。
- 发消息 / 群发 / 同步这类**有副作用**的调用，务必先确认账号——**发错号不可撤销**。
- 数据是按账号分目录/分行的：聊天记录按 `<account_id>` 分目录，事件流按 `<account_key>` 分目录，SQLite 表里有 `account_id` 列。

## 6. 数据覆盖度与口径（务必写进对接方的文档）

| 口径 | 含义 | 常见误用 |
|---|---|---|
| **落盘历史**（`chat_history` / MCP 的 history 工具） | 由监控型 AI 助理**机会式采集**，**可能有缺口**，不是连续录制 | 拿它当"完整聊天记录" |
| **当前窗口快照**（约 5 条） | 只读当前聊天窗**可见**的最后一屏 | 拿它做"总结一天消息"→ 必漏 |
| **会话索引** | 只有"被采集过"的会话才在索引里 | 索引里没有 ≠ 微信里没有 |

对接方在按时间段取数时，必须处理"该时间段是否被覆盖"的问题：覆盖不到时应明确返回"无法判断"，**不要**用更早的数据顶替，也不要替客户断定原因。

## 7. 风险与红线

**必须遵守：**

1. **不做数据外发**。所有通道都只在 `127.0.0.1` 回环；不要做端口转发/公网映射。MCP 服务明确拒绝带 `Origin` 的请求，就是防止被网页脚本盗用。
2. **`protected/agent-secrets.v1.json`、MCP token、RPA 临时凭据一律不外泄**，不写入日志、不进代码仓库、不进提示词。
3. **写操作单独审批**。发消息、群发、发圈、加好友、改配置都会真实影响客户，对接方必须做人工确认与幂等保护；`wechat_send_message` 超时**不要自动重发**（可能重复触达）。
4. **不要直接杀进程 / 改 RPA 目录**来"修"问题。异常时按顺序：先只读诊断 → 等待自动恢复 → 仍失败再由人确认后重启。
5. **暴露范围最小化**。对外只放白名单技能（当前仅 `wechat-rpa`）；`shell`、`filesystem`、`scheduler`、`task_group`、`agent_records`、`mcp` 永不外露。

**已确认的能力边界（别对外承诺）：**

| 想要的 | 实际 | 结论 |
|---|---|---|
| 每个好友的头像 | `wechat_contacts.db` 无头像列；同步流水线不持久化头像；微信原生头像缓存 RPA 不读 | ❌ **拿不到** |
| 实时监控群消息 | 只有机会式采集的落盘历史 + 当前窗口快照 | ❌ 不存在"实时流" |
| 群聊里 @ 某人 | RPA 无 @ 发件人能力（回复里写 `@张三` 只是文字） | ❌ 做不到 |
| 完整微信历史记录 | RPA 不读微信 `WeChat Files` | ❌ 只有被采集过的部分 |

## 8. 最小可用示例

### 8.1 Python：读 MCP（会话索引 → 消息）

```python
import json, urllib.request

ENDPOINT = "http://127.0.0.1:<对外页端口>/mcp"
TOKEN    = "<对外页 token>"

def rpc(method, params=None, req_id=1):
    body = json.dumps({"jsonrpc": "2.0", "id": req_id, "method": method,
                       "params": params or {}}).encode()
    req = urllib.request.Request(ENDPOINT, data=body, method="POST", headers={
        "Content-Type": "application/json",
        "Authorization": f"Bearer {TOKEN}",
    })
    with urllib.request.urlopen(req, timeout=120) as r:
        return json.load(r)

# 1) 列出已采集的会话
sessions = rpc("tools/call", {"name": "wechat_list_history_sessions", "arguments": {}})
print(sessions["result"]["content"][0]["text"])

# 2) 读某个会话的记录（account_id / session_id 来自上一步）
msgs = rpc("tools/call", {"name": "wechat_get_history_messages",
                          "arguments": {"account_id": "<ACCOUNT_ID>",
                                        "session_id": "<session_id>"}}, req_id=2)
if msgs["result"]["isError"]:
    raise RuntimeError(msgs["result"]["content"][0]["text"])
print(msgs["result"]["content"][0]["text"])
```

### 8.3 Python：增量读客户事件（JSONL）

```python
import glob, json, os
root = os.path.expanduser("~/.webot/data/customer_events_v1/accounts")
for f in sorted(glob.glob(f"{root}/*/events/*/*.jsonl")):
    with open(f, encoding="utf-8") as fh:
        for line in fh:                      # 每行一个事件，逐行解析
            line = line.strip()
            if not line:
                continue
            ev = json.loads(line)
            print(ev["occurred_at"], ev["event_type"], ev["result"]["status"])
```

> 注意：`max_records: 10000`、`max_bytes: 16MB` 会触发轮转；按天分文件，采集方要按文件顺序增量消费并自行去重（`event_id` 全局唯一）。
