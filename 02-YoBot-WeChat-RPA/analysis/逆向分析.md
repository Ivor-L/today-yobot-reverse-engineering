# YoBot 微信 bot 逆向分析

分析日期：2026-09-20。对象：本机 YoBot 1.3.5 和安装在其 plugins 目录的 wechat-rpa 1.9.19。结论来自本地静态文件，未进行线上接口验证。

## 已恢复内容

- `recovered/app/`：ASAR 内 21,911 个条目（含依赖），并从 app.asar.unpacked 合并外置文件。Electron 主进程和大量业务模块是带命名、注释的可读 JavaScript。
- `recovered/wechat-rpa/frontend-sources/`：source map 内 1,264 条源码内容，含第三方依赖和重复编译视图，并非 1,264 个独立业务组件。原始路径映射见 `frontend-sources.json`。
- `recovered/wechat-rpa/bytecode/`：1,603 个 Python 模块的 marshal 字节码，其中 WeRobotCore 321 个模块。
- `recovered/wechat-rpa/disassembly/`：WeRobotCore 等模块的 Python 3.9 反汇编。它们是字节码指令与常量，不是恢复后的 Python 源码。
- `recovered/wechat-rpa/native/`：原生 Helper 可执行文件副本；符号、字符串、动态库清单保存在 analysis 目录。

## 微信功能的两条实际注册路径

`recovered/app/dist/server.cjs:735496` 注册 WeChatAdapter；735500 行创建 WechatIlinkAdapter，随后注册到 gateway。因此这两条路径不仅有孤立文件，也存在于服务器启动代码。

### 桌面微信 RPA

调用关系：YoBot gateway → WeChatAdapter → 本机 HTTP/WebSocket → Python WeRobotCore → 签名的 macOS Helper → 微信界面。

关键代码：

- `dist/electron/channels/wechat.js`：监听 `/ws` 的 `new_message` 事件，将 content、session_name、session_id、account_id 等转换为 Agent 消息；回复向 `/api/chat/send_message` POST `{user, message}`，附 X-API-Key。
- `dist/electron/utils/rpa_port.js`：默认 9922，候选 9923–9930。macOS 主进程管理模式通过 IPC 提供运行时凭据，不应把兼容默认值当作生产密钥。
- `dist/electron/services/yokowebot/client.js`：register/registered 握手，订阅 wechat.* 和 ai.* 告警；与普通 new_message 消息路径不同。
- `dist/electron/electron/macos_control_driver.js`：启动 YokoWebotRpaControl，并管理运行时身份和连接。
- Python `WeRobotCore.host.macos_mvp_chat`、`macos_mvp_realtime`、`macos_agent_compat`：聊天、实时消息和 Agent 兼容层的分析入口。
- Python `WeRobotCore.adapters.wechat.macos_ax` 子模块：微信适配、监控、启动及 Helper IPC 契约。

Helper 是 arm64 Mach-O，包含 Swift 运行时引用，依赖 AppKit、ApplicationServices、CoreGraphics、ScreenCaptureKit、Vision。字符串中有 AXUIElement/CGEvent；Python 模块文档也明确描述 Accessibility 会话列表读取和 Helper 中的前台校验。这些证据支持“界面自动化控制微信”的判断。仅凭这些证据不能排除程序其它部分采用其它技术。

### iLink

调用关系：扫码绑定 → 保存凭据 → getupdates 长轮询 → dispatchToAgent → gateway/Agent → sendText/sendItem 回复。

关键代码目录：`dist/electron/channels/wechat_ilink/`。

- `client.js`：基础地址常量为 ilinkai.weixin.qq.com；实现 get_bot_qrcode、get_qrcode_status、getupdates，以及发送和媒体上传。使用 Bearer bot token。此处仅记录程序实现，未确认服务当前对外可用性。
- `adapter.js`：绑定状态、轮询、输入附件、去重/游标推进、队列命令和 Agent 转发。774 行起 dispatchToAgent 构造稳定消息 ID，并保存 context_token 以供回复。
- `credential_store.js`、`state_store.js`：凭据抽象和轮询状态存储。
- `media.js`、`vision.js`：媒体处理。

## 恢复边界与后续维护

可直接阅读和修改提取后的 JS；但这不是原始开发仓库。原始 TypeScript 类型、构建配置、开发脚本和测试未完整恢复。安装包的 package.json 未提供完整开发构建流程。

Python 控制层已经解包并可按模块阅读反汇编，尚未还原成经验证的可维护 .py。原生 Helper 仅完成静态识别，尚未恢复 Swift 源码。若目标是完全独立重建桌面微信控制器，需要继续对这些模块做语义恢复或按已确认契约重写，并验证 macOS 权限、签名和微信版本兼容性。

恢复后代码没有启动，因此尚未验证真实账号的收发、绑定或可重新打包运行。未修改原始安装包，未读取聊天数据库或登录凭据。

## 校验和复现

在工作目录执行 `python3 tools/extract_asar.py` 可复现 ASAR 提取。packed 文件验证大小与可用 SHA-256；unpacked 文件以本机实际外置文件为准，记录哈希，但不要求匹配 ASAR 内原大小/哈希（实际发现一个外置 native 文件大小不同）。`extraction-manifest.json` 保存逐文件记录和 ASAR 总哈希。

使用 Python 3.9 执行 `python3 tools/extract_plugin.py` 可复现插件 source map、PyInstaller CArchive/PYZ 提取和业务反汇编。字节码解析与反汇编不执行应用代码。版本差异可能导致 marshal 解析失败。

已通过 Node 语法检查：wechat.js、wechat_ilink/adapter.js、wechat_ilink/client.js。这只能证明语法可解析，不证明真实服务可运行。
